# Independent cache recovery for generated graphs

Stage 3 of the [roadmap](roadmap.md) uses the complete generated
[HTTP](project-sync-http-full.md) and [Immutable](project-sync-immutable-full.md)
graphs. The producer and consumer are separate Linux ARM64 containers with
SDK 10.0.400 and Bazel 9.2.0. This is HTTP action-cache qualification, not remote
execution or a new source-built runtime-host qualification.

## Isolation and acquisition

The producer seeded a new bazel-remote cache, then stopped. The consumer had no
mounts, no producer outputs, no user NuGet cache and no prior Bazel output base.
Its workspace moved from `.../full-generated-driver/FAMILY/upstream` to
`.../relocated/FAMILY`. The rules checkout also moved. Only declared workspace
inputs, generated declarations, raw test reports and hash manifests were transferred.

Package archives were excluded from that transfer. The consumer independently
fetched their recorded public feed URLs and verified each declared SHA-256:

| Graph | Archives | Bytes downloaded | Acquisition wall time |
| --- | ---: | ---: | ---: |
| HTTP | 121 | 177,685,552 | 20.534 s |
| Immutable | 66 | 182,195,692 | 13.864 s |

The SDK and runner remain declared Bazel repository/action inputs. Immutable's
installed-host files are explicit workspace inputs; HTTP uses its declared SDK
host because tests invoke SDK tooling. No user package directory or producer
filesystem fills in missing inputs.

## Recovery results

| Recorded action | HTTP remote hits | Immutable remote hits |
| --- | ---: | ---: |
| Assembly compilation | 44 / 44 | 38 / 38 |
| Package extraction | 121 / 121 | 131 / 131 |
| Generation | 1 / 1 | — |
| Layout construction | — | 14 / 14 |
| Reference/implementation pairing | — | 10 / 10 |
| SDK host construction | 1 / 1 | — |
| Build runner bootstrap | 1 / 1 | 1 / 1 |
| Test result | 1 / 1 | 1 / 1 |
| **Total build/test actions** | **169 / 169** | **195 / 195** |

Immutable has 36 generated project producers, an authored assembly-load probe,
and an analyzer compiled in both target and execution configurations. These give
38 compilation actions; action counts are not project counts. Package extraction
likewise includes configuration-specific instances.

All **5,294 HTTP** and **490 Immutable** recorded reference/runtime/layout output
hashes match. Cached test recovery and forced fresh test execution both retain
714 exact HTTP outcomes and 22,544 normalized Immutable outcomes. The Immutable
startup hook confirms that tests load the recovered source-built implementation.
Relocated `//:sync --check` preserves generated bytes, and each separate sync-runner
bootstrap is also a remote hit.

Recovery wall times were 25.736 s for HTTP and 16.735 s for Immutable, including
fresh Bazel setup and repository acquisition. Forced tests took 2.743 s and
16.532 s respectively. These are single correctness runs, not the repeated
raw-MSBuild performance comparison planned for stage 7.

## Invalidation controls

With the producer still stopped, both recovered graphs pass body, API and declared
resource edits. Public references remain stable for body/resource changes and
change for API edits. HTTP recompiles 1/28/1 assemblies respectively; Immutable
recompiles 2/3/2. Each edit preserves unrelated targets, and each restoration
recompiles zero assemblies by recovering baseline results. Tests retain raw parity;
body/API changes execute tests again. Immutable retains its loaded-source hash check.

See [compact evidence](project-sync-remote-cache-evidence.json). No production
cache or path-handling correction was needed for these two generated graphs.

## Reproduce

Prepare both graphs with the stage-2 driver. For each family:

1. Run `cache_packages.py record WORKSPACE MANIFEST --package-root NUGET_ROOT`
   (repeat `--package-root` for any explicit acquisition cache). This records feed
   origins and verifies archives against the authored package rules.
2. Run the seed with a fresh cache. An existing producer output base is cleaned
   before seeding, so actions are uploaded rather than merely read locally:

   ```sh
   python3 tests/project_sync/upstream/remote_graph.py \
     WORKSPACE PRODUCER_BASE RAW_TRX SEED_JSON \
     --family http --cache http://CACHE:8080 --seed
   ```

3. Transfer workspace inputs to a different path in a separate container. Exclude
   `bazel-*`, `locked-packages/` and `bootstrap-packages/`. Transfer the rules
   checkout, raw report, acquisition manifest and seed JSON separately. Update only
   the authored `local_path_override` to the consumer rules path.
4. Run `cache_packages.py acquire CONSUMER_WORKSPACE MANIFEST`. It requires the
   archives to be absent, downloads them in four parallel requests, and rejects a
   digest mismatch. Stop the producer before recovery.
5. Run the same `remote_graph.py` command using the consumer paths, an absent output
   base and `--expect SEED_JSON` instead of `--seed`. It requires every recorded
   build action and the test result to hit remotely, compares output hashes,
   forces fresh tests, verifies raw parity and checks relocated synchronization.
6. Run `remote_mutations.py WORKSPACE BASE SEED_JSON NEW_REPORT_DIRECTORY
   --family http --cache http://CACHE:8080` for body/API/resource edits and restoration.

Use `--family immutable` and its corresponding raw report for the other graph.
Both harnesses explicitly disable disk caching. Consumers disable uploads, so
restoration tests recover the original producer results. Preserve execution logs
and BEP files alongside reports; compact committed evidence summarizes them.
