# Native VSTest action contract

`prepare_graph.prepare(..., tests=[{"node": configured_id, "data": [workspace_relative_paths], "expectedTests": [fully_qualified_names]}])` publishes explicit test targets. The equivalent CLI option is `--tests JSON_FILE`. Run `bazel test //:test_<configured_id>`; use `--nocache_test_results` when evidence requires actual execution after cache recovery.

The native Bazel `test=True` rule consumes sealed graph bundles, the declared SDK, a standalone .NET runner, and explicitly hashed test data. It selects exactly one bundle by project and all configured global properties, verifies its artifacts, and stages its runtime directory into fresh writable scratch. It invokes the SDK's `vstest.console.dll` directly: no MSBuild build or restore runs during the test. The runtime directory includes the built test adapter and testhost closure. This interface currently selects net10.0 under SDK 10.0.100.

The runner sets `SHOULDLY_SOURCE_PATH_MAP=<fresh staged workspace>=/_/workspace`, reversing the compiler's stable PathMap. Only declared source/approval data is staged. Upstream test sources and approval behavior remain unchanged. VSTest requires loopback IPC between its console and testhost; the rule retains native sandbox execution but does not set `block-network`. This is not evidence of a completely closed host runtime or network isolation.

Bazel retains `report.json`, `results.trx`, `test.log`, and any `received/` files in standard test undeclared outputs, including failing runs. Pass `--zip_undeclared_test_outputs` to collect them in `test.outputs/outputs.zip`. `XML_OUTPUT_FILE` receives a JUnit invocation result. Exit zero requires the exact expected test names/count, every outcome Passed, VSTest exit zero, and no timeout. Zero-test discovery is a failure. Report fields include actual TRX counters/results, the invocation, declared data/runtime hashes, and failure diagnostics. `buildOrRestoreInvoked=false` describes the runner's direct invocation contract, not instrumentation of arbitrary user test code.

## Validation and scope

`python3 -m unittest discover -s tests/test_action -v` exercises test-data publication and rejects missing, escaping, duplicate data or empty/duplicate expected names. The native test is opt-in via `SERILOG_SOURCE` and `SERILOG_PACKAGES`; it archives the pinned unchanged upstream revision and builds a pathmapped ordinary assembly before deleting that checkout. `tools/probe_test_action.py --source PATH --packages PATH --output FRESH_PATH` is the same independently runnable protocol. It checks a passing actual Fact, changed and missing approved-data failures, and zero-test failure, with retained structured results.

The ordinary-runtime prototype is not the graph-built upstream acceptance gate. The separate Serilog test adapter acceptance track must prove graph build/replay, producer-free relocation, recovered bytes, and actual test execution. Linux validation is deferred. Native macOS ARM64 validation passed all four controls at `/private/tmp/serilog-test-rule-prototype-3/report.json`: positive (1 passed), changed approval (1 failed), missing approval (1 failed), and zero tests (0, rejected). Every test executed under `darwin-sandbox`; all retained TRX/report outputs and the ordinary build checkout was absent. The blocked-network control independently produced a testhost loopback connection abort, explaining the explicit IPC requirement. This correctness run overlapped other track work; elapsed times are not benchmark claims. ActionRunner contract/process tests passed with exact pinned asset-role enforcement for approval packages.

The standalone prototype requires the SDK repository empty-external-import glob correction from the integration track. The recorded native run used that correction in its copied fixture; the probe itself does not patch production rules.
