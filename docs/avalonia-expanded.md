# Expanded Avalonia qualification

This extends the [remote Avalonia slice](avalonia-remote-execution.md) with larger
upstream suites, managed libraries, and Desktop/Skia. It is correctness coverage,
not a performance comparison or whole-repository support claim.

## Qualified coverage

The combined graph contains **13 entries, 40 distinct project files, 53 configured
project nodes, 55 compilation actions, and 5 IDL generation actions**. Some tools
are built in both target and execution configurations.

| Upstream suite | Passed | Skipped |
| --- | ---: | ---: |
| Base | 2,334 | 14 |
| Controls | 2,421 | 1 |
| Markup.Xaml | 580 | 1 |
| Skia | 257 | 9 |
| Skia rendering | 290 | 17 |
| **Total** | **5,882** | **42** |

Raw and Bazel test names and outcomes match exactly. The separate managed-library
slice also matches raw reference bytes, embedded resources, and compiled XAML
method identities across all 26 configured projects.

Both **Bazel 8.8.0 and 9.2.0** passed:

- Cold remote execution: 55 compilations, 5 generations, and all five suites.
- No-op: no compilation, generation, or test execution.
- Independent recovery: **291/291 observed actions were cache hits**, including
  test results, on a separate client disk and workspace path. Only source inputs
  were transferred; no output base or local outputs were copied.

The generic test-directory support also passed 41 analysis tests per Bazel
version, 35 runner unit tests, and 12 xUnit/NUnit/MSTest controls. Repository and
.NET style checks passed. [Compact evidence](avalonia-expanded-evidence.json)
records action counts, outcome digests, and managed artifact comparisons.

## Inputs and boundaries

The source is Avalonia **11.3.12**, commit
`37fbd9655cc581ff5b1c6b1fb1be4e3118c889d0`, with DataGrid submodule
`85a0b32ef6d963c1d67619ca3e2f6da0bc43ac9a`. Entries target `net8.0`, retaining
selected `netstandard2.0` helper configurations. Raw controls and Bazel use SDK
10.0.400, Release, and the same pinned VSTest 17.14.1 runner and xUnit adapter.
Test execution rolls forward to the declared .NET 10 host in both controls.

Execution uses the SDK-free Ubuntu 22.04 ARM64 worker described in
[remote execution](remote-execution.md). Inputs include:

- Explicit configured project edges, private dependencies, and assembly choices.
- Project-built analyzers and Avalonia's XAML build tasks.
- Five separate MicroCom IDL generation actions. Consumers use their outputs;
  raw-generated C# files are removed from the Bazel workspace. Generated bytes
  are compared against the raw outputs.
- D-Bus XML files with their `DBusGeneratorMode` metadata preserved explicitly.
- Skia/HarfBuzz native assets from locked NuGet archives, plus eight hash-pinned
  Fontconfig dependencies and six DejaVu fonts declared as runtime data.
- Rendering baseline images and a relative `tests` runtime directory. No original
  checkout is exposed to the remote test process.

The native fixture requires the exact Linux ARM64 files listed in
`tests/explicit_msbuild/avalonia/native-inputs.json` during preparation. It verifies
hashes and sends copies as Bazel inputs; the worker does not need Fontconfig or
fonts installed. Both raw and Bazel tests use the same explicit
[Fontconfig configuration](https://fontconfig.pages.freedesktop.org/fontconfig/fontconfig-user.html),
including default and Courier New/Arial/Times aliases. An initial raw control
without those declarations failed the Courier New width test. No tests or test
assertions are patched or filtered to compensate.

Desktop compilation includes managed Windows/macOS/X11 backends. It does **not**
qualify running Windows or macOS UI, opening Linux display windows, GPU drivers,
Android/iOS workloads, browser/WASM, packaging, or every sample. Skia rendering
coverage is offscreen CPU rendering. Headless XUnit/NUnit/VNC libraries are
compiled and compared; that does not qualify VNC networking or every runner
integration. Raw/Bazel reference-byte equality is asserted for the managed-library
slice. It is not claimed for Desktop COM stubs: `Avalonia.Win32.Automation` has
compiler-generated file-local type names containing path hashes. Its inspected
type/member metadata matches after normalizing only those hashes.

## Reproduce

Use a fresh directory for each prepared slice and each result. Set
`RULES_MSBUILD_DOTNET_ROOT`, `RULES_MSBUILD_BAZEL`, `USE_BAZEL_VERSION` (`8.8.0` or
`9.2.0`), and substitute your executor address below. Preparation performs raw
restore/build and exports explicit declarations; it is outside Bazel execution.
Initialize `external/Avalonia.Controls.DataGrid` at its pinned submodule revision.

```sh
python3 tests/explicit_msbuild/avalonia/setup.py /path/to/avalonia /tmp/core \
  --entry tests/Avalonia.Base.UnitTests/Avalonia.Base.UnitTests.csproj \
  --entry tests/Avalonia.Controls.UnitTests/Avalonia.Controls.UnitTests.csproj \
  --entry tests/Avalonia.Markup.Xaml.UnitTests/Avalonia.Markup.Xaml.UnitTests.csproj
python3 tests/explicit_msbuild/avalonia/expanded.py /tmp/core /tmp/core-results \
  --test Avalonia.Base.UnitTests --test Avalonia.Controls.UnitTests \
  --test Avalonia.Markup.Xaml.UnitTests --executor grpc://WORKER_IP:8980

python3 tests/explicit_msbuild/avalonia/setup.py /path/to/avalonia /tmp/managed \
  --entry src/Avalonia.Themes.Fluent/Avalonia.Themes.Fluent.csproj \
  --entry src/Avalonia.Controls.ColorPicker/Avalonia.Controls.ColorPicker.csproj \
  --entry src/Avalonia.Diagnostics/Avalonia.Diagnostics.csproj \
  --entry src/Avalonia.Fonts.Inter/Avalonia.Fonts.Inter.csproj \
  --entry src/Headless/Avalonia.Headless.XUnit/Avalonia.Headless.XUnit.csproj \
  --entry src/Headless/Avalonia.Headless.NUnit/Avalonia.Headless.NUnit.csproj \
  --entry src/Headless/Avalonia.Headless.Vnc/Avalonia.Headless.Vnc.csproj
python3 tests/explicit_msbuild/avalonia/expanded.py /tmp/managed /tmp/managed-results \
  --executor grpc://WORKER_IP:8980

python3 tests/explicit_msbuild/avalonia/setup.py /path/to/avalonia /tmp/desktop \
  --entry src/Avalonia.Desktop/Avalonia.Desktop.csproj \
  --entry tests/Avalonia.Skia.UnitTests/Avalonia.Skia.UnitTests.csproj \
  --entry tests/Avalonia.Skia.RenderTests/Avalonia.Skia.RenderTests.csproj
python3 tests/explicit_msbuild/avalonia/expanded.py /tmp/desktop /tmp/desktop-results \
  --test Avalonia.Skia.UnitTests --test Avalonia.Skia.RenderTests \
  --executor grpc://WORKER_IP:8980
```

For the combined check, pass all thirteen entry paths above to one `setup.py`
invocation, then pass all five `--test` names to `expanded.py`.

The first build disables action-cache reads and requires every compilation and
generation action to execute remotely. The next run must execute no compilation
or tests. Reports contain per-case raw/Bazel outcome parity; managed-library
reports additionally compare reference bytes, embedded resources and compiled
XAML method identities. Raw or Bazel failures stop qualification.

For independent recovery, copy only a prepared slice's `bazel` directory,
excluding `bazel-*` symlinks and all output bases, to another Linux client. Then:

```sh
python3 tests/explicit_msbuild/avalonia/expanded.py /consumer/slice \
  /consumer/fresh-results --recover --executor grpc://WORKER_IP:8980
```

Recovery rewrites the local rules override, requires all observed actions to be
cache hits, and verifies the cached per-case test outcomes. The executor and cache
must preserve the producer's instance namespace recorded in the copied manifest.
